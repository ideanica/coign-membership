Buat halaman baru pada project **coign-membership** untuk layanan **Web Development**, yang berfungsi sebagai landing page sekaligus pricing/service page untuk menawarkan jasa pembuatan website dan custom web system.
halaman ini terpisah dari home, namun buatkan card kecil untuk memberi tahu bahwa kami punya paket yang ditawarkan yang akan dilink kan dengan halaman ini. lalu jangan lupa untuk menambahkan menu-item Packages di navbar.
lalu aku notice setiap kali baru load halaman landing page untuk responsive mobile selalu ada terlihat seperti navbar yang awalnya melebar kebawah dengan tidak rapi menampilkan seluruh menu-item, seperti navbar panjang halaman desktop yang dipaksakan menyesuaikan halaman sempit mobile. perbaiki itu juga.

## 1. Sebelum mulai

Sebelum menulis kode:

1. Inspect struktur project yang sudah ada.
2. Identifikasi:
   - framework yang digunakan,
   - routing,
   - design system,
   - typography,
   - spacing,
   - reusable components,
   - button styles,
   - card styles,
   - color palette,
   - navbar,
   - footer,
   - responsive breakpoints,
   - animation style bila ada.
3. Gunakan kembali component yang sudah tersedia sebanyak mungkin.
4. Jangan membuat visual identity baru.
5. Halaman baru harus terasa sebagai bagian native dari Coign Membership.
6. Jangan mengubah halaman lain kecuali benar-benar dibutuhkan untuk navigation menuju halaman baru.
7. Jangan melakukan refactor besar yang tidak berhubungan dengan task ini.

Jika project sudah memiliki pola route untuk service/product pages, ikuti pola tersebut.

Gunakan route yang paling konsisten dengan struktur project, misalnya:

`/web-development`

Jika struktur routing project menggunakan prefix lain, sesuaikan.

# 16. UX Requirements

Pastikan:

- Fully responsive
- Mobile-first behavior diperhatikan
- Tidak ada horizontal overflow
- Pricing cards tetap readable di mobile
- CTA mudah ditemukan
- Heading hierarchy benar
- Accessible contrast
- Buttons mempunyai hover/focus states
- Semantic HTML
- Keyboard-accessible FAQ
- No duplicated IDs
- Tidak menggunakan hardcoded viewport hacks
- Avoid excessive animations

Jika existing site memiliki animation library, boleh gunakan secara subtle.

Jangan tambahkan library besar hanya untuk animasi sederhana.

# 17. Engineering Requirements

- Reuse existing components terlebih dahulu.
- Pisahkan data package dari presentation bila architecture project memungkinkan.
- Hindari satu component raksasa.
- Gunakan component reusable untuk:
  - PricingCard
  - FeatureList
  - Comparison
  - FAQ
  - CTA
  - Section headings
- Gunakan naming dan folder convention existing project.
- Jangan membuat dependency baru jika tidak perlu.
- Jangan mengubah global styling secara agresif.
- Pastikan existing pages tidak regress.

Jika project menggunakan TypeScript, jangan menambahkan `any` tanpa alasan.

Jika project mempunyai lint/test/build command, jalankan setelah implementasi.
